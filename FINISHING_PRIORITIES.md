# StudentOS: what to finish before a college pilot

Updated 21 October 2026. This is a prioritized product and engineering assessment, not a claim that the local presentation dataset is a real institution deployment.

| Priority | Work | A useful completion check |
| --- | --- | --- |
| 1 | Activate the isolated coding runner | Student Python, Java and C++ submissions execute with enforced CPU, memory, file and network limits; hidden cases and failed jobs produce truthful results. The six browser JavaScript exercises and SQLite labs already work, but are a smaller practice experience. |
| 1 | Connect institution email and test real onboarding | A staff invitation, student enrollment, recovery link and deadline reminder arrive in a real mailbox. Invitation scope, expiry, retries and recovery are exercised on staging. |
| 1 | Review the learning and readiness model with faculty | Agree role-specific assessment blueprints and prerequisites. Add topic-level mastery, missed-question remediation, richer BI/data/cloud/security exercises and distinct long-term milestones. A four-year calendar needs more reviewed content than the current 158 lessons. |
| 1 | Deploy an institution staging environment | Separate real accounts from fictional history; configure HTTPS/domain, backups and restore drills, storage, monitoring and alert ownership. Prove roster access boundaries, file handling, recovery and an agreed retention/deletion process. |
| 2 | Turn advice into reviewed interventions | Quid now calculates named cohorts and suggests seven-day support plans. Add a reviewed “create support plan” handoff, a shared faculty/student goal, scheduled check-in and comparison with the next assessment. Existing outreach/intervention records provide part of this foundation. Quid must not silently send messages or change plans. |
| 2 | Keep jobs and events fresh | Activate an authorized opportunity feed, closed-listing refresh, saved searches and opt-in notifications. Add an owner for campus event updates and company eligibility rules; public listings and inferred study-year tags are not confirmed campus drives. |
| 2 | Evaluate AI across representative questions | A live Gemini response is now available using a locally configured model, with authorized server context and record-based fallback. Add repeated quality checks for names, counts, ambiguous student references, unsupported questions, sample versus verified evidence, latency and cost. The exact report remains the source of truth. |
| 3 | Deepen presentation and optional integrations | Add licensed video chapters and playback progress when content is selected; improve resume export with real student examples. GitHub/LeetCode sync, voice interviews, hosted project terminals, study groups and SSO are useful later additions rather than prerequisites for every local workflow. |

The current app already covers the main student, teaching and placement navigation. The next work should make these connected workflows deeper and dependable rather than adding more top-level menus.
