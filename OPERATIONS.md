# StudentOS operations

The supported local pilot architecture is one Node service/worker with persistent SQLite and private upload storage. Node 24 is the tested runtime. Several domains still use JSON aggregates; do not run multiple app workers against the queue without implementing leased job claiming.

A separate low-volume Vercel presentation adapter is described in [DEPLOYMENT.md](DEPLOYMENT.md). It uses a freshly generated fictional campus, private Blob snapshots and conditional writes; it is not the institution pilot architecture described below.

## Run and validate

```powershell
npm ci
npm run dev
npm run check
npm test
npm run build
```

Development uses the website at `http://127.0.0.1:5180` and API at `http://127.0.0.1:5080`. After building, `npm start` serves the built website and API together at port 5080. The Vite watcher excludes `data/` and `.runtime/`. Assessment ZIPs are regenerated by the prebuild step.

`npm run verify` runs check, tests and build. `npm run format` parses and reformats source through atomic file replacement. These are syntax/scope checks, not a complete type checker. The Vite build also rejects server or private scoring modules entering browser bundles; public lesson-title metadata is separate from scored lesson data. The example workflow in `scripts/github-ci.example.yml` runs install/check/test/build when installed with the required GitHub permissions. `scripts/cua-smoke.mjs` contains the browser checks for the documented browser tab API; it does not launch Playwright independently.

`npm run load:check` starts a disposable in-memory 500-person fixture on port 5099, sends 50 state requests with concurrency five, checks catalog gzip/ETag behavior, writes `.runtime/load-check.json`, then stops that fixture. Run it separately from resource-heavy builds/tests for a useful local comparison. It does not edit the persistent campus and does not prove large-scale production capacity.

## Institution setup

Production requires `NODE_ENV=production` and an HTTPS `APP_ORIGIN`. Set `COLLEGE_ID` and `COLLEGE_NAME` to the real institution, matching the bootstrap identity. Set `HOST`, `PORT` and `STUDENTOS_DATA_DIR`; keep the data directory outside disposable release folders. A database with sample accounts is refused in production. Keep the populated HKBK sample store separate.

Initialize the real institution with `node scripts/admin.mjs`. Supply a JSON object on standard input containing `collegeId`, `college`, `name`, `handle`, `email` and a password of at least 12 characters. Use a secure input mechanism; do not put passwords in command arguments, checked-in files or shell history. The administrator can invite staff/students, validate a CSV roster, approve pending public registrations, correct academic records, assign roles and suspend access. Public registration cannot grant staff privileges.

Student self-reported profile changes cannot set verified CGPA/backlog/graduation eligibility. Academic changes are recorded with the acting administrator and timestamp. They preserve the student's active session; suspension or role changes revoke sessions. Password recovery also revokes old sessions. The last active administrator cannot be removed through the account UI.

Put the service behind an HTTPS reverse proxy restricted to the configured origin. `TRUST_PROXY=1` trusts forwarded client addresses only when the connecting proxy is loopback; configure that proxy to replace incoming forwarded headers. Secure/HttpOnly cookies, origin checks, CSP, no-sniff and production HSTS headers are emitted by the service. The parent application does not permit `unsafe-eval`; browser JavaScript runs in a separate opaque-origin sandbox with network access denied. This browser practice is not a trusted server exam.

## Backup and recovery

`npm run backup` makes an online SQLite snapshot in the configured data directory's `backups/`. It verifies integrity, counts profiles, writes a SHA-256 manifest `<backup>.json`, and copies every referenced private attachment to `<backup>.files/`. Soft-deleted files retained for submitted academic records are included. Keep the SQLite file, manifest and attachment directory together. Backup creation fails when referenced bytes are missing or have the wrong size.

Copy successful backup sets to institution-controlled storage with restricted access, a retention schedule and an off-machine copy. They contain private campus records, messages and credential hashes. The script does not implement off-site replication or retention deletion.

Restore into a new, empty destination:

```powershell
node scripts/restore.mjs <backup.sqlite> <new-directory>/studentos.sqlite
```

The command validates database integrity/checksum and attachment hashes. It refuses to overwrite an existing database or nonempty upload destination. Old database-only backups are usable only when they reference no files. For recovery, stop the app, set `STUDENTOS_DATA_DIR` to the restored directory, restart, then verify sign-in, college counts, submissions/attachments and queue status before switching traffic. Preserve the previous directory until recovery is accepted. If a restore fails, inspect the partial new destination and choose a fresh directory for another attempt.

The latest recorded drill and its limitations are in [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md). A local restore drill does not replace a scheduled off-machine recovery exercise.

## AI adapter

Choose one server-only AI connection. For native Gemini, set `AI_PROVIDER=gemini`, `GEMINI_API_KEY` and `GEMINI_MODEL` to an available model ID for your account. The adapter uses Google’s `generateContent` endpoint and an `x-goog-api-key` header, with native system instructions and JSON output for scored reviews. See [Google’s API reference](https://ai.google.dev/api/generate-content). No live key is bundled. Optional `GEMINI_FALLBACK_MODELS` is a comma-separated ordered list of up to two alternate model IDs. Unavailable, rate-limited and timed-out requests can fail over; invalid authorization is returned immediately. Choose models supported by the account and review their cost and availability.

For an OpenAI-compatible endpoint, set `AI_PROVIDER=compatible`, `QUID_BASE_URL`, `QUID_API_KEY` and `QUID_MODEL`. The base URL includes the provider API prefix, such as `/v1`; the server appends `/chat/completions`. Never prefix secrets with `VITE_`. Restart after changing environment variables.

The provider receives the entered prompt and bounded, selected workspace context. Interviews send resume/project/job context only when selected in the interface. Generated resume edits require review and apply/undo. Without configuration, navigation and saved guided practice work, and no provider-generated interview score is claimed. Test one real lesson explanation, resume proposal and full interview, inspect data-sharing expectations, and confirm provider cost/latency before activation. Quid rebuilds context from current server records for each question. Students receive only their own academic context. Faculty require academic-read permission and are restricted to their college; explicit out-of-scope student IDs are rejected. Full names, handles and student IDs resolve to a student, while ambiguous names ask for selection. Conversations are separated by student context. Bounded context includes plan/activity, demonstrated skills, scored attempts, assignments/feedback, project evidence, resume/application/interview preparation and authorized mentor notes. College questions include aggregate skill/coursework summaries and query-relevant candidate records. Private DMs, passwords and API keys are excluded. Academic activity must not be interpreted as personality, intent or a reason for absence. Local fallback responses identify sample data and do not simulate an AI answer. Gemini transport and failover are covered by mocked tests. The local development setup has returned a live grounded Quid answer using Gemini 3 Flash; every deployment still needs its own credentials and representative quality, cost and latency checks. `.env` is ignored by Git and deliberately not loaded by memory-database HTTP tests. College reports calculate filters, counts and scores on the server, exclude unassessed skills from rankings and attach the exact searchable/exportable result. Generated suggestions supplement that report. If the provider fails, Quid returns direct academic analysis with an availability notice.

## Transactional mail adapter

Set `MAIL_WEBHOOK_URL`, `MAIL_WEBHOOK_TOKEN` and `MAIL_FROM`. The service sends a Bearer-authenticated POST with JSON `{from,to,subject,text}` and a 15-second timeout. Production endpoints must use HTTPS. Return 2xx only after the institution's chosen mail provider accepts delivery. A 2xx adapter response does not establish inbox delivery.

The durable queue retries failed mail up to five attempts with backoff, releases interrupted work on startup and deduplicates reminders. Administration shows delivery state/errors. Prove staff invitation and recovery links arrive, are institution-scoped, expire and can be used only once. In-app reminders work locally; no external email delivery has been verified in this workspace.

## Authorized opportunity feed

Set `OPPORTUNITY_FEED_URL` to an HTTPS JSON-array feed and optionally `OPPORTUNITY_FEED_TOKEN`. Automatic refresh is queued hourly when configured; administrators can queue a refresh or import JSON manually. The whole batch is validated before mutation. Limit: 1–500 records and a 2 MB feed response.

Required record fields: `sourceUrl` (HTTPS original page), `company`, `title`, `description`, `eligibility`, `country`, `years` (array containing 1–4), and `skills` (nonempty subset of DSA, Frontend, Backend, Databases, DevOps, Communication). Optional fields: `location`, `type` (Internship, Apprenticeship or Full-time), `requirements` (array), `availability` (open/closed), `closesAt`, `duration` and `compensation`. Source URL deduplicates records; a refresh updates the existing opportunity. Check time is set by StudentOS. Missing records in a later batch are not automatically deleted or marked closed; the feed should explicitly send closed status or a deadline.

The original 35 sourced opportunities remain a dated snapshot. An import does not create an employer partnership or submit an application externally. Independently verify feed authorization and freshness before describing listings as live.

## Trusted coding runner contract

Set `JUDGE_URL` and `JUDGE_TOKEN` for a separately isolated execution service. HTTPS is required outside loopback. This app implements a client contract, not the execution infrastructure. Do not point it at an ordinary process that executes submissions with application/database access.

Request: Bearer-authenticated POST with `version:1`, `language` (`javascript`, `python`, `java`, `cpp`), `source`, `functionName`, `tests:[{args:[...]}]` and `limits:{cpuMs:2000,memoryMb:128,outputBytes:16384,network:false,filesystem:'ephemeral'}`. Implement language-specific function invocation in the runner. Expected answers stay in StudentOS and are not sent to that service.

Response: `{results:[{actual:<JSON value>,error?:<string>}],durationMs?:number,memoryKb?:number}` with exactly one result per test. StudentOS compares actual outputs to its private expected answers, records the run, and awards the first solve once. The adapter has a 20-second timeout and bounded accepted response size. A provider-reported success flag is insufficient. Only six original function problems are currently supported. Contract behavior is tested with a fake service; actual execution in all four languages and the provider's resource/network isolation remain unverified until a real runner is connected.

## Monitoring and release

`/api/health` probes SQLite and reports configured/unconfigured AI/mail/judge dependencies. It does not actively call each provider. Every request gets an ID; production request logs include method, path without query/body, status and duration. Administration exposes recent p95/memory/uptime and durable job/audit records. Institution-owned log collection, retention, error alerts, provider dashboards and uptime checks still need hosting integration.

For each release, retain the source commit, built bundle, compatible environment configuration and a successful backup set. Test on a separate staging data directory. Stop the prior single worker before starting the new one. Verify health, authentication, a student learning submission, staff review, scoped social access and attachment download. If validation fails, stop the new service and restore the previous source/bundle; schema changes may require restoring the corresponding database and files into a new directory. Do not downgrade a changed database blindly.

A final hosting/domain, HTTPS deployment, external service checks, privacy/retention agreement, independent security/dependency review and broader accessibility/concurrency review remain release gates. There is no automatic cloud deployment in this repository.

## Presentation content and course completion records

The local HKBK fixture retains 400 students and 100 staff. The additive `hkbk-presentation-content-v1` dataset adds 44 posts and 12 events exactly once; it preserves profile edits, earned course progress and existing community history. The seed runs only with the populated development campus, and production still rejects sample-account stores. The presentation data provenance is retained in storage and described in Settings; repetitive sample badges are removed from daily student/staff views.

`node scripts/import-brand-assets.mjs` refreshes 61 local company marks with source attribution; `--refresh` bypasses validated cached assets. `node scripts/import-profile-assets.mjs` downloads 128 CC0 illustrated portraits and verifies sizes/hashes. `node scripts/import-learning-resources.mjs` records HTTP status and title metadata for 24 official learning links. `node scripts/import-employer-opportunities.mjs` refreshes a bounded 60-posting public employer metadata snapshot; official board origins and source hosts are checked. It makes no employer applications and stores no full advert bodies or salaries. Existing curated posting IDs take precedence during the 94-record merge. Each row retains source and retrieval dates. This is a refresh command, not a scheduled live feed.

A complete StudentOS course unlocks its own completion record. New completion timestamps are saved only after successful server checks; imported learning history remains identified as such without invented dates. Certificates use a stable record ID, identify StudentOS Learning as issuer, and are generated as escaped SVG at an authenticated endpoint scoped to the current learner. Incomplete courses return 404. External provider credentials are not issued automatically. The interface supports SVG download and a print layout for the browser’s Save as PDF action; no third-party PDF renderer is required.
